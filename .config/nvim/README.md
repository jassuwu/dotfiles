# nvim

Neovim 0.12 config. No plugin manager DSL, no LSP framework, no completion engine —
core handles all three. 11 plugins, installed with the built-in `vim.pack`.

```
init.lua              leader, requires
lua/options.lua       vim.o, incl. native completion
lua/plugins.lua       PackChanged hook, vim.pack.add, setup() calls
lua/keymaps.lua       only maps that are NOT core defaults
lua/autocmds.lua      yank highlight, restore cursor
lua/lsp.lua           vim.lsp.enable, diagnostics, LspAttach
lua/treesitter.lua    parser install + FileType hooks
after/lsp/*.lua       per-server overrides, auto-discovered by core
nvim-pack-lock.json   generated by vim.pack — commit it, never hand-edit
```

## Updating plugins

There is no `:Lazy` UI. Update, then commit the lockfile:

```
:lua vim.pack.update()
```

That opens a confirmation buffer; `:w` applies, `:q` aborts. It rewrites
`nvim-pack-lock.json` in this directory — **commit that file**, it is the only thing
making the plugin set reproducible. `nvim-treesitter` tracks a branch rather than a tag,
so the lockfile is doing real work.

Other entry points: `:lua vim.pack.get()` to list, `:lua vim.pack.del({'name'})` to
remove, `:checkhealth vim.pack` to check the lockfile against what's on disk.

## Language servers come from Homebrew, not Mason

A missing server is `brew install`, never `:MasonInstall`. Current set:

```
brew:   lua-language-server gopls rust-analyzer tree-sitter fd stylua gofumpt \
        goimports taplo marksman shfmt ruff clang-format
npm -g: @vtsls/language-server @tailwindcss/language-server \
        vscode-langservers-extracted @biomejs/biome prettier basedpyright
```

`clangd` is Apple's at `/usr/bin/clangd`. `clang-format` is a separate Homebrew
formula, not part of Apple CLT. `tree-sitter` **must** come from Homebrew — the npm
build fails silently with the `main` branch.

Python: ruff lints, basedpyright types. `after/lsp/ruff.lua` turns off ruff's hover so
basedpyright owns `K`. Rust: `rust-analyzer` plus `rustfmt` from rustup.

## Completion

Native, via `'autocomplete'` in `lua/options.lua`. Accept with `<C-y>`; `<Tab>` and
`<S-Tab>` jump snippet placeholders (both are core defaults). `<CR>` is left alone.

If this ever proves unsatisfying, the escape hatch is `blink.cmp` — **pinned**, because
`main` is a breaking V2 that also needs a separate `saghen/blink.lib`:

```lua
{ src = 'https://github.com/Saghen/blink.cmp', version = vim.version.range('1.*') },
```

On a v1 tag it downloads prebuilt binaries and falls back to a pure-Lua matcher, so no
Rust toolchain is needed.

## Things that will bite

- `vim.pack` has **no lazy-loading** — no `event`/`ft`/`cmd`/`keys`. That's the trade.
- `PackChanged` must be registered *before* the first `vim.pack.add()` or build hooks
  never fire.
- Server overrides go in `after/lsp/`, not `lsp/` — core merges `after/` last, so
  `nvim-lspconfig`'s data wins over yours if you get this backwards.
- Never `require('lspconfig')`. It's a data directory now; the framework errors in v3.
- `vim.pack` version pinning needs `v1.2.3`-shaped tags. `v1` and `1.2` don't parse.
